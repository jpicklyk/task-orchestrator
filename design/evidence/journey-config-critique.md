# Critique of journey-config-fit.md

Method: every grade re-checked against source (config schema and validator, transition table and policy, decision service, run-planner, hooks, create-item, manage-schemas profiles), not the docs. Paths: KT = `current/src/main/kotlin/io/github/jpicklyk/mcptask/current/`, PLUG = `claude-plugins/task-orchestrator/`, CR = `current/docs/config-reference.md`.

Headline: the fit misses two mechanisms that move six grades. (1) A decision raised with `block: true` blocks the item as `awaiting_decision`, works with an item id alone (no run), and a `human-only` class can only be answered by a human credential. (2) The retrospective `scope` boundary already fires per completed scope item. A third gap is the ten YAML reference profiles in manage-schemas.

## Root-cause corrections

1. **"No acceptance in the config model" double-counts and mixes causes.** R2 does not belong (no acceptance needed for a revisable note). R18 does not belong (the retro mechanism exists; the gap is R8). R10 is a different cause: the lifecycle graph is fixed and has no backward edge (the catalogue's "Known limits"), not a missing acceptance. R9 is one cause (no acceptance trigger). The mechanism the statement says is absent exists in part: a blocking human-only decision. Restate as: no link from a phase or note to a decision class, so a human gate is a convention the orchestrator must keep (an answer does not resume, `decisions.md:60-62`).
2. **"Notes have no declared part" is a plugin-contract issue.** Fix the framing (see R24): the plugin already hard-codes keys and types. Drop R2 from it.
3. **"Build vs build-nothing is missing" is overstated.** Replace with: a type cannot declare "born blocked" or "never built"; the BLOCKED plus decision route does both after creation. Add that the planner treats any item with children as a container.
4. **"The director has no config surface" carries R11 wrongly.** R11 has config keys. The cause covers R13 alone, and R13 is conduct that the host's project instructions carry.
5. **"Plugin-side settings scattered" mixes four different things.** R14 is hook behaviour with one mode key; R16 is partly E; R21 is a plugin library, not a setting; R22 is a missing version marker (top-level schema is `additionalProperties:false`, `extensions` is unread). Split R22 off.
6. **"Setup has no library" is wrong and double-counts R21 and R22 with cause 5.** The library exists (ten YAML profiles plus advisor). The gap is that `init` and `quick-start` do not call it and J7's light config has only `schema-free`. R22 is unrelated to a library.
