# Plugin hooks

Hook entrypoints live in this directory and are wired by `hooks-config.json`. Shared plumbing lives in `lib/`;
every module is pure at import (no top-level I/O) and never throws.

| Module | Role |
|--------|------|
| `lib/stdin.mjs` | `readHookInput()` / `parseHookInput(text)`: hook stdin as a plain object, or `null` when unreadable. |
| `lib/emit.mjs` | Output builders (`contextOutput`, `denyOutput`, `blockOutput`, `systemMessageOutput`) and the matching one-write stdout writers (`emit`, `emitEmpty`, `emitContext`, `emitDeny`, `emitBlock`, `emitSystemMessage`). |
| `lib/markers.mjs` | Temp-dir marker files: `sessionMarkerPath` (per session), `sharedMarkerPath` (cross-session), `readMarker`, atomic `writeMarker`, `createMarkerOnce`. |
| `lib/envelope.mjs` | `parseToolResult` reads the 4.0 result envelope (`kind` and `retryAfterMs` as the server sends them); `isLegacyShape` flags a 3.x payload. |
| `lib/ops.mjs` | `opsOf`, `selectOf`, `opItemIds`, `resultItemIds`: helpers over the `ops` array of a tool input and its result. |
| `lib/api-client.mjs` | URL and token discovery, `fetchWithTimeout`, `callOp(tool, body)` over `POST /api/v1/ops/{tool}`, and `wellKnown()`. |
| `lib/server-compat.mjs` | `assessServer` / `checkServer` (major 4 with the `seats` feature) and `legacyShapeWarningOnce`. |
| `lib/tool-names.mjs` | Generated by `scripts/gen-call-shapes.mjs`: `TOOLS`, `PROFILES`, `WRITE_TOOLS` and `ERROR_KINDS`. |

## Hooks on the envelope

The write-path hooks read the 4.0 contract, not the 3.x one. `phase-guard-record` (PostToolUse `advance` and `items_read`) and
`dispatch-hint` parse `tool_response` with `parseToolResult` and read every `results[i]`: an element is recordable when
`ok` with a `newRole` (`gate_blocked` records nothing: it means a note is missing). A phase-owner seat (`implementer` or
`reviewer`) already in its phase sends no `start`, so its first item-mode context read is recorded instead, when the
item's role is the one the seat owns and nothing is recorded yet; a non-empty top-level `seatToken` marks a run seat,
which is never recorded. A 3.x-shaped result records and hints
nothing and shows the legacy-shape warning once per session. `phase-guard` (SubagentStop) reads each recorded item's
gate with `items_read` `select: "context"` (`POST /api/v1/ops/items_read`) and skips `workflow-subagent`. It blocks a stopping seat only on that seat's own missing notes: when the gate carries `missingBySeat` and the view's `seats` names the stopping seat, only `missingBySeat[seat]` counts (the `unowned` bucket and other seats' keys never block); otherwise it falls back to the flat `missing` list minus the test-author-owned keys (kept when the stopping seat is the test author).
`skill-enforcement` (PreToolUse `notes_write`) acts on `ops[]` elements with `op: "upsert"` and takes skill and
`maxLength` facts from the server: one `config` `effective` read per session, cached in a session marker, and the
item's `items_read` `schema` view per op. The attribution hook is removed. With a located config and no REST API
URL, `phase-guard` and `skill-enforcement` emit one `systemMessage` per session saying so (gate state and schema
facts come from the server) and then stay silent; `phase-guard-record` is always silent.

The REST base URL resolves in this order: `TASK_ORCHESTRATOR_API_URL`, a project-level `client.json` (loopback only), the origin of the orchestrator's http(s) MCP registration (local `~/.claude.json` project entry, then `.mcp.json` - loopback only - then user `~/.claude.json`; `lib/mcp-registrations.mjs`), then the user-level `client.json`. `session-start` adds one warning line when the env var or a `client.json` points at a different origin than the registration.

## Mode gating

Plugin keys live under `extensions.claude-code` in `.taskorchestrator/config.yaml` (for example
`extensions.claude-code.orchestration.mode`). Top-level 3.x keys such as `orchestration:` are ignored; a 4.0 server
rejects them on push, and `session-start` prints a `## Config Shape` line when it finds one.

`execution-mode.suppressionReason(hookInput, env)` is the shared gate for the four injecting context hooks. It returns
`headless` (`TASK_ORCHESTRATOR_MODE=headless-iteration`), then `subagent` (a non-empty `agent_id`), then `director` (a
file exists at `directorMarkerPath(session_id)`, written by `director-guard.mjs` when the director skill is invoked), or `null`.
