# Plugin hooks

Hook entrypoints live in this directory and are wired by `hooks-config.json`. Shared plumbing lives in `lib/`;
every module is pure at import (no top-level I/O) and never throws.

| Module | Role |
|--------|------|
| `lib/stdin.mjs` | `readHookInput()` / `parseHookInput(text)`: hook stdin as a plain object, or `null` when unreadable. |
| `lib/emit.mjs` | Output builders (`contextOutput`, `denyOutput`, `blockOutput`, `systemMessageOutput`) and the matching one-write stdout writers (`emit`, `emitEmpty`, `emitContext`, `emitDeny`, `emitBlock`, `emitSystemMessage`). |
| `lib/markers.mjs` | Temp-dir marker files: `sessionMarkerPath` (per session), `sharedMarkerPath` (cross-session), `readMarker`, atomic `writeMarker`, `createMarkerOnce`. |
| `lib/envelope.mjs` | `parseToolResult` reads the 4.0 result envelope (`kind` and `retryAfterMs` as the server sends them); `isLegacyShape` flags a 3.x payload. |
| `lib/ops.mjs` | `opsOf`, `selectOf`, `opItemIds`, `resultItemIds`: helpers over the `ops` array of a tool input and its result. |
| `lib/api-client.mjs` | URL and token discovery, `fetchWithTimeout`, `callOp(tool, body)` over `POST /api/v1/ops/{tool}`, and `wellKnown()`. |
| `lib/server-compat.mjs` | `assessServer` / `checkServer` (major 4 with the `seats` feature) and `legacyShapeWarningOnce`. |
| `lib/tool-names.mjs` | Generated by `scripts/gen-call-shapes.mjs`: `TOOLS`, `PROFILES`, `WRITE_TOOLS` and `ERROR_KINDS`. |

`api-client.mjs` in this directory is a re-export shim of `lib/api-client.mjs`; it is removed once the remaining
callers move to `callOp`.

## Hooks on the envelope

The write-path hooks read the 4.0 contract, not the 3.x one. `phase-guard-record` (PostToolUse `advance`) and
`dispatch-hint` parse `tool_response` with `parseToolResult` and read every `results[i]`: an element is recordable when
`ok` with a `newRole`, or `gate_blocked` (the item and the phase it already sits in come from `error.detail`); a
non-empty top-level `seatToken` marks a run seat, which is never recorded. A 3.x-shaped result records and hints
nothing and shows the legacy-shape warning once per session. `phase-guard` (SubagentStop) reads each recorded item's
gate with `items_read` `select: "context"` (`POST /api/v1/ops/items_read`) and skips `workflow-subagent`.
`skill-enforcement` (PreToolUse `notes_write`) acts on `ops[]` elements with `op: "upsert"` and takes skill and
`maxLength` facts from the server: one `config` `effective` read per session, cached in a session marker, and the
item's `items_read` `schema` view per op. The attribution hook is removed. With a located config and no REST API
URL, `phase-guard` and `skill-enforcement` emit one `systemMessage` per session saying so (gate state and schema
facts come from the server) and then stay silent; `phase-guard-record` is always silent.
